# МАС локализации и тушения лесных пожаров

Многоагентная система для лабораторных работ по курсу «Теория многоагентных систем».
Штаб, дроны-разведчики, пожарные расчёты и точки заправки совместно обнаруживают и тушат
лесные пожары на карте с ветром, частичной наблюдаемостью и ограниченными ресурсами.

## Что внутри

| Каталог | Содержание |
|---|---|
| `wildfire_mas/env/` | Среда: процедурная карта, стохастический клеточный автомат огня с ветром, физика действий, наблюдения |
| `wildfire_mas/comm/` | Сообщения в духе FIPA ACL (перформативы, диалоги, подписи) и шина с задержками, потерями и радиусом радиосвязи |
| `wildfire_mas/agents/` | Агенты: штаб (`hq.py`), дрон (`drone.py`), пожарный расчёт BDI (`crew.py`), точка заправки (`water.py`); интерфейс с наименьшими привилегиями (`base.py`) |
| `wildfire_mas/coordination/` | Механизмы распределения задач: централизованная диспетчеризация (жадная и венгерский алгоритм — собственная реализация), контрактная сеть, аукцион первой и второй цены |
| `wildfire_mas/llm/` | LLM-режим штаба: клиент OpenAI-совместимого API (LM Studio), промпт, валидатор ответа, откат на правила |
| `wildfire_mas/metrics.py` | Показатели качества: ущерб, потерянные посёлки, время ликвидации, сообщения, справедливость |
| `wildfire_mas/web/` | Веб-демонстрация: FastAPI + WebSocket + Canvas |
| `tests/` | Тесты (pytest) |

Все протоколы и логика агентов реализованы явно, без готовых агентных фреймворков.

## Установка и запуск

Нужен [uv](https://docs.astral.sh/uv/) (он сам установит Python 3.12 и зависимости).

```bash
uv sync                    # окружение и зависимости
uv run wildfire serve      # веб-демонстрация: http://127.0.0.1:8000
```

В веб-интерфейсе выбираются сценарий, seed, механизм распределения задач, режим штаба
(правила / LLM), число агентов, ветер и потери связи. Можно запустить моделирование
непрерывно или по шагам. Переключатели над картой показывают карту убеждений штаба
(пунктир), сообщения такта, радиусы связи, маршруты расчётов и зоны дронов.
Ссылку можно параметризовать: `/?scenario=windy&mechanism=cnp&seed=3&autoplay=100&belief=1`.

### Командная строка

```bash
# один прогон, показатели в JSON (+ сравнение с прогоном без агентов)
uv run wildfire run --seed 3 --mechanism cnp --baseline

# трасса выполнения (JSONL: состояние агентов и все сообщения на каждом такте)
uv run wildfire run --seed 3 --trace runs/trace.jsonl

# серия экспериментов: все механизмы × seed 1..20 → CSV
uv run wildfire batch --mechanisms all --seeds 1-20 --out runs/lab2.csv

# любой параметр модели: --set key=value
uv run wildfire run --set n_crews=3 p_loss_cmd=0.2 wind_speed0=8
```

Механизмы: `central_greedy`, `central_hungarian`, `cnp`, `auction_first`, `auction_vickrey`, `cnp_drone` (торги от дронов по радио, без штаба).

Эксперименты ЛР 2 (все механизмы × 3 сценария × 30 пожаров, масштаб, потери связи, графики) запускаются одной командой:

```bash
uv sync --extra analysis
uv run wildfire lab2 --seeds 30 --out results/lab2
```
Сценарии: `default`, `calm_single`, `windy`, `outbreak`.

### LLM-режим штаба

Роль координатора может исполнять языковая модель, например Qwen в LM Studio,
доступная по Tailscale через OpenAI-совместимый API:

```bash
export LLM_BASE_URL=http://<адрес-машины-в-tailscale>:1234/v1
export LLM_MODEL=<идентификатор модели в LM Studio>
uv run wildfire run --hq llm --seed 1
uv run wildfire serve      # и выбрать «Штаб: LLM»
```

Ответ модели (JSON-план) проверяется валидатором: существуют ли агенты и задачи, соблюдаются ли
полномочия и лимиты мест. Невалидные назначения отбрасываются. Если модель недоступна или
ответ невалиден, штаб откатывается на правила. Донесения передаются модели как данные в
отдельном блоке, и системный промпт запрещает исполнять содержащиеся в них указания.

## Соответствие лабораторным работам

| Работа | Где в коде |
|---|---|
| ЛР 1. Спецификация и архитектура | вся система |
| ЛР 2. Распределение задач и координация | `coordination/`, `experiments.py`, `wildfire lab2` |
| ЛР 3. Переговоры и конфликты | политика очереди точки заправки (`WaterPointAgent.order_queue`), приоритеты задач, валидатор |
| ЛР 4. Диверсионный анализ и надёжность | шина (потери, подписи), heartbeat и тайм-ауты штаба, LLM-валидатор, трассы |
